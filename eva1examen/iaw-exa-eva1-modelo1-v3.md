### 2. Solucionario y Rúbrica de la Parte de Desarrollo

#### Solución Pregunta 1 (Git — Ramas y Conflictos)
- **1. Crear y cambiar de rama (0,3 Puntos):**
  ```bash
  git checkout -b sistema-usuarios
  # O alternativamente:
  # git branch sistema-usuarios
  # git checkout sistema-usuarios
  ```
- **2. Volver a main y fusionar (0,3 Puntos):**
  ```bash
  git checkout main
  git merge sistema-usuarios
  ```
- **3. Resolución del conflicto (0,4 Puntos):**
  - Al detectar el conflicto, Git marca las diferencias en el archivo `config.php` usando los delimitadores `<<<<<<< HEAD`, `=======` y `>>>>>>> sistema-usuarios`.
  - El desarrollador debe abrir `config.php` con un editor, seleccionar manualmente el código correcto y eliminar las marcas de conflicto.
  - Guardar el archivo, añadirlo a la zona de staging (`git add config.php`) y confirmar la resolución realizando un commit (`git commit -m "Resuelto conflicto en config.php"`).

#### Solución Pregunta 2 (Apache — Host Virtual)
- **1. Directorio y Permisos (0,3 Puntos):**
  ```bash
  sudo mkdir -p /var/www/html/tienda
  sudo chown -R www-data:www-data /var/www/html/tienda
  sudo chmod -R 755 /var/www/html/tienda
  ```
- **2. Archivo `/etc/apache2/sites-available/tienda.conf` (0,4 Puntos):**
  ```apache
  <VirtualHost *:80>
      ServerName tienda.local
      DocumentRoot /var/www/html/tienda
      
      <Directory /var/www/html/tienda>
          Options -Indexes +FollowSymLinks
          AllowOverride All
          Require all granted
      </Directory>

      ErrorLog ${APACHE_LOG_DIR}/tienda_error.log
      CustomLog ${APACHE_LOG_DIR}/tienda_access.log combined
  </VirtualHost>
  ```
- **3. Activación y Recarga (0,3 Puntos):**
  ```bash
  sudo a2ensite tienda.conf
  sudo systemctl reload apache2
  ```

#### Solución Pregunta 3 (MySQL — Base de Datos y Usuarios)

  -- 1. Crear la base de datos (0,3 Puntos)
  CREATE DATABASE bd_wordpress DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

  CREATE USER 'wp_user'@'localhost' IDENTIFIED BY 'ClaveSegura2026!';

#### Solución Pregunta 4 (CMS — Roles y Permisos)
- **1. Comparación de privilegios entre Editor y Colaborador (0,5 Puntos):**
  - **Editor:** Posee control total sobre la gestión de contenidos. Puede crear, editar, publicar y eliminar **cualquier** entrada o página del sitio web, independientemente de quién sea el autor, además de moderar comentarios y gestionar categorías.
  - **Colaborador:** Es un rol restringido a la redacción. Puede crear y editar únicamente sus propios borradores de entradas, pero **no tiene permiso para subir archivos multimedia ni para publicar entradas**.
- **2. Justificación del flujo de trabajo e intervención (0,5 Puntos):**
  - La restricción del Colaborador es una medida de seguridad y control editorial. Impide que redactores externos o nuevos miembros publiquen contenidos no supervisados.
  - El artículo redactado por un Colaborador queda en estado "Pendiente de revisión". Para hacerse público en el frontend, debe ser revisado, aprobado y publicado por un usuario con perfil de **Editor** o **Administrador**.

#### Solución Pregunta 5 (CMS — Seguridad y Copias de Seguridad)
- **1. Componentes indispensables a respaldar (0,3 Puntos):**
  - **Archivos de la aplicación web:** Incluye los archivos del núcleo (core) del CMS, plantillas/temas, plugins y especialmente el directorio de subidas multimedia (`wp-content/uploads` en WordPress) junto a los archivos de configuración (`wp-config.php`).
  - **Base de Datos relacional (MySQL/MariaDB):** Almacena todo el contenido dinámico del sitio: entradas, páginas, usuarios, contraseñas, comentarios, opciones del sitio y configuraciones de plugins.
- **2. Procedimiento de respaldo (0,4 Puntos):**
  - **Base de Datos:** Se respalda exportando su estructura y datos mediante la herramienta de consola `mysqldump -u wp_user -p bd_wordpress > backup_bd.sql` o a través de plugins como *UpdraftPlus*.
  - **Archivos:** Se respaldan comprimiendo la carpeta web en un archivo empaquetado `tar -czvf backup_files.tar.gz /var/www/html/tienda` o descargándolo por SFTP/plugins.
- **3. Justificación de la Regla 3-2-1 (0,3 Puntos):**
  - **3 copias:** La versión original más 2 respaldos para prevenir la corrupción del archivo de copia.
  - **2 soportes distintos:** Guardar las copias en medios físicos/lógicos diferentes (ej. disco local SSD y servidor NAS/disco externo) para evitar fallos por avería de hardware.
  - **1 copia fuera de las instalaciones (Offsite):** Guardar al menos una copia en un servicio de almacenamiento en la nube (Google Drive, AWS S3, etc.) para garantizar la recuperación ante un desastre físico en el centro de datos (incendio, inundación o robo).
